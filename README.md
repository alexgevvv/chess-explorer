# Chess Explorer

A browser-based chess analysis board and personal opening explorer for Chess.com games. It can also open as a Telegram Mini App.

## Run locally

Requires Node.js 24 or newer.

```sh
npm ci
npm run dev
```

Open the address printed by Vite. On Windows, use `npm.cmd` in PowerShell or double-click `Run-Chess-Explorer.cmd`.

## Features and data

- Import standard Rapid, Blitz and Daily games for a Chess.com nickname. Bullet, variants and unfinished games are excluded.
- Games and completed archives are stored per nickname in IndexedDB on the current device. Imports resume after cancellation; Update checks missing and the two latest archives.
- Next-move counts, frequency and win/draw/loss statistics follow the board position, including transpositions and opponent replies. Flip the board to choose the player's White or Black games.
- The starting White position shows five moves; other positions show all matching continuations. Filters cover time control, UTC completion date and opponent rating.
- Matching games, variation navigation, FEN/PGN import and a position editor.
- Local Stockfish 19 analysis with White-perspective evaluation, best move, optional arrow and principal variation.
- Telegram or system light/dark theme.

Frequency includes games ending in the position in its denominator. Win rate is wins divided by games containing that continuation; draws do not count as half-wins. A repeated position counts once per game, at its first occurrence.

There is no backend database or cross-device sync. Clearing site data can remove saved games. Nickname selection, settings and analysis branches reset on reload. Chess.com requests go directly from the browser to its public API.

## Checks

```sh
npm test
npm run lint
npm run build
```

Browser checks require Microsoft Edge and a running app:

```sh
npm run dev -- --port 5174 --strictPort
npm run test:browser
```

Set `TEST_BASE_URL` to test another address. `verify-production.mjs` defaults to a Vite preview server on port 4173. `verify-live-api.mjs` makes real Chess.com requests and depends on network and archive availability.

## Build and deploy

`npm run build` generates `dist`. Upload the contents of that folder to static hosting. `python package-release.py` creates upload and source ZIPs after a build. The packaging script requires Python 3.

Keep the same hostname to retain access to the existing device cache. Configure the deployed HTTPS URL as the Telegram bot's menu button; no bot token belongs in this frontend.

## Structure

`App.tsx` coordinates the interface. `board.ts` manages analysis branches; `data.ts` computes position statistics; `data.worker.ts` runs parsing and queries off the UI thread. `importer.ts` downloads archives, `storage.ts` stores them, and `engine.ts` manages Stockfish.

Stockfish assets in `public/engine` are generated by the predev/prebuild script from the pinned npm package. Its GPLv3 license and source references are copied alongside the engine. Preserve these notices when distributing builds.

Large histories can take time to import and query. Browser Worker, WebAssembly and IndexedDB support are required; behavior inside Telegram still needs verification on target phones.
